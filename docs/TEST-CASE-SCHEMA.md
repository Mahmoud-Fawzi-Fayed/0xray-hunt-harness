# Test Case Schema

## Test Plan Case (`testplan.py`)

Each test case generated by `build_test_plan()`:

```json
{
  "case_id": "a1b2c3d4e5f67890",
  "method": "GET",
  "endpoint": "/api/v1/users/{id}/orders",
  "params": ["id"],
  "category": "idor",
  "priority": "high",
  "signals": ["handles_identity", "state_changing"],
  "owner": "user_a",
  "accessor": "user_b",
  "role": "user_b",
  "status": "pending"
}
```

### Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `case_id` | string | Yes | 16-hex-char deterministic hash of (method, endpoint, sorted params, category, role, owner, accessor) |
| `method` | string | Yes | HTTP method (GET, POST, PUT, PATCH, DELETE) |
| `endpoint` | string | Yes | URL path or full URL |
| `params` | string[] | Yes | Parameter names involved in this test |
| `category` | string | Yes | Vulnerability class slug (idor, xss, sqli, bac, deep, etc.) |
| `priority` | string | Yes | One of: critical, high, medium, low |
| `signals` | string[] | Yes | Signal patterns detected on this endpoint |
| `owner` | string | No | Identity that owns the resource (for auth boundary tests) |
| `accessor` | string | No | Identity attempting access (for auth boundary tests) |
| `role` | string | No | Role context for this test case |
| `status` | string | Yes | pending, running, tested, blocked, inconclusive, disproved, confirmed |
| `test` | string | Yes | Test instruction text generated from endpoint profile |
| `priority_score` | int | No | Numeric priority for sorting (higher = test first) |
| `confidence` | string | No | Discovery confidence: high, medium, low |
| `guidance_text` | string | No | Knowledge-driven guidance for the hunt agent |
| `recommended_skills` | string[] | No | Skill file names from `skill_map.py` |
| `body` | object | No | Request body template for write-method cases |
| `body_params` | string[] | No | Body parameter names from discovery |

### Case ID Generation

```python
def case_id(case):
    canonical = json.dumps({
        "accessor": case.get("accessor") or "",
        "category": case.get("category") or case.get("vuln_class") or "",
        "method": (case.get("method") or "GET").upper(),
        "owner": case.get("owner") or "",
        "params": sorted(case.get("params") or []),
        "role": case.get("role") or "",
        "url": case.get("endpoint") or case.get("url") or "",
    }, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(canonical.encode()).hexdigest()[:16]
```

Properties:
- SHA-256 based (not MD5), truncated to 16 hex chars (64-bit)
- Deterministic: same inputs always produce the same ID
- Canonical JSON ensures key order independence
- Primary key in state, coverage, evidence, and plan index

### Signal Patterns

| Signal | Meaning | Maps to |
|--------|---------|---------|
| `handles_identity` | Endpoint takes user/account IDs | IDOR, BOLA, BFLA |
| `accepts_file` | File upload parameters | Unrestricted upload, path traversal |
| `accepts_url` | URL/redirect parameters | SSRF, open redirect |
| `accepts_freetext` | Search/comment/template params | XSS, SSTI, injection |
| `auth_flow` | Login/signup/OAuth paths | Token issues, account takeover |
| `elevated_privilege` | Admin/manage paths | Privilege escalation |
| `financial` | Payment/billing endpoints | Price manipulation, race conditions |
| `state_changing` | POST/PUT/PATCH/DELETE | CSRF, business logic |

## State Key Format

### Current (5-field pipe-delimited)

```
METHOD|URL|PARAMS|CATEGORY|ROLE
```

Example: `GET|/api/users|id|idor|user_b`

### Legacy (4-field, backward compatible)

```
METHOD|URL|PARAM|VULN_CLASS
```

`coverage.py::_parse_tested()` handles both formats. Hash-based keys (16-hex from `case_id()`) are the primary lookup.

## Coverage Matrix Keys

Coverage tracked by 7-tuple to prevent overclaim:

```
(method, url, category, param, role, owner, accessor)
```

A roleless test case does NOT credit a role-specific surface item.
