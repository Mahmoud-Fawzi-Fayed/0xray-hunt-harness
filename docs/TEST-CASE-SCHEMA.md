# Test Case Schema

## Test Plan Case (`testplan.py`)

Each test case generated by `build_test_plan()`:

```json
{
  "case_id": "a1b2c3d4e5f67890",
  "method": "PATCH",
  "endpoint": "/api/v1/users/42/orders",
  "params": ["id", "amount"],
  "category": "dynamic",
  "priority": "high",
  "signals": ["input_variation", "state_and_sequence", "ownership_boundary"],
  "trust_dimensions": ["input_variation", "state_and_sequence", "ownership_boundary"],
  "function_profile": {"profile_id": "f0e1d2c3b4a59687", "protocol": "http"},
  "dimension_results": {},
  "owner": "user_a",
  "accessor": "user_b",
  "role": "user_b",
  "status": "pending"
}
```

### Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `case_id` | string | Yes | 16-hex-char deterministic hash of (method, endpoint, sorted params, category, role, owner, accessor) |
| `method` | string | Yes | HTTP method (GET, POST, PUT, PATCH, DELETE) |
| `endpoint` | string | Yes | URL path or full URL |
| `params` | string[] | Yes | Parameter names involved in this test |
| `category` | string | Yes | `dynamic` for behavior analysis or `boundary` for actor/resource cases; legacy classes remain readable |
| `priority` | string | Yes | One of: critical, high, medium, low |
| `signals` | string[] | Yes | Alias of the function profile's trust dimensions, not vulnerability patterns |
| `trust_dimensions` | string[] | Yes | Independent trust assumptions that each require their own result |
| `function_profile` | object | Yes | Protocol-neutral action/resource, actor, input, effect, state, sensitivity, and provenance model |
| `dimension_results` | object | No | Per-dimension hypothesis, status, observation IDs, evidence, and blocked reason |
| `hypothesis_ledger` | object[] | No | Append-only dimensional outcomes and overall case history |
| `owner` | string | No | Identity that owns the resource (for auth boundary tests) |
| `accessor` | string | No | Identity attempting access (for auth boundary tests) |
| `role` | string | No | Role context for this test case |
| `status` | string | Yes | pending, running, tested, blocked, inconclusive, disproved, confirmed |
| `test` | string | Yes | Behavior-specific instruction generated from the function profile |
| `priority_score` | int | No | Numeric priority from observed impact and unresolved trust |
| `confidence` | string | No | Discovery confidence: high, medium, low, observed, inferred, or unknown |
| `guidance_text` | string | No | Reserved compatibility field; empty during pre-hypothesis planning |
| `recommended_skills` | string[] | No | Reserved compatibility field; empty until live evidence and a hypothesis exist |
| `body` | object | No | Request body template for write-method cases |
| `body_params` | string[] | No | Body parameter names from discovery |

### Case ID Generation

```python
def case_id(case):
    canonical = json.dumps({
        "accessor": case.get("accessor") or "",
        "category": case.get("category") or case.get("vuln_class") or "",
        "method": (case.get("method") or "GET").upper(),
        "owner": case.get("owner") or "",
        "params": sorted(case.get("params") or []),
        "role": case.get("role") or "",
        "url": case.get("endpoint") or case.get("url") or "",
    }, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(canonical.encode()).hexdigest()[:16]
```

Properties:
- SHA-256 based (not MD5), truncated to 16 hex chars (64-bit)
- Deterministic: same inputs always produce the same ID
- Canonical JSON ensures key order independence
- Primary key in state, coverage, evidence, and plan index

### Trust Dimensions

| Dimension | Meaning |
|-----------|---------|
| `actor_variation` | Behavior may differ across authenticated actors or roles |
| `ownership_boundary` | A resource has an owner whose boundary needs evidence |
| `tenant_boundary` | An organization, account, or tenant boundary exists |
| `input_variation` | Accepted inputs can be varied and require independent outcomes |
| `content_and_parser_variation` | Body, file, header, or cookie parsing assumptions exist |
| `state_and_sequence` | Mutations, preconditions, replay, or second-order state need testing |
| `external_effect` | A callback, integration, or downstream call crosses a boundary |
| `file_handling` | File content and lifecycle require their own hypotheses |
| `role_transition` | Role changes may alter authorization or workflow state |
| `protocol_behavior` | Non-HTTP protocol behavior needs protocol-specific evidence |
| `relationship_boundary` | A response, artifact, or operation declares a relationship whose boundary needs evidence |
| `workflow_logic` | An observed multi-step invariant requires sequence and precondition evidence |
| `data_confidentiality` | Observed sensitivity requires disclosure and access-control evidence |

Dimensions describe observed behavior, not vulnerability classes or mandatory test menus. Callers may add dimensions for observed behavior not represented by these names. Every applicable dimension starts pending or unknown and resolves only through its own evidence-linked result. Profiles also retain `relationships`, `logic_invariants`, and `residuals`; operation-level execution never implies complete dimensional or target coverage.

## State Key Format

### Current (7-field pipe-delimited)

```
METHOD|URL|PARAMS|CATEGORY|ROLE|OWNER|ACCESSOR
```

Example: `GET|/api/users|id|idor|user_b|A|B`

### Legacy (4-field, backward compatible)

```
METHOD|URL|PARAM|VULN_CLASS
```

`coverage.py::_parse_tested()` handles both formats. Hash-based keys (16-hex from `case_id()`) are the primary lookup.

## Coverage Matrix Keys

Legacy class coverage uses a 7-tuple to prevent cross-method, parameter, role, or ownership credit:

```
(method, url, category, param, role, owner, accessor)
```

Dimensional coverage additionally keys each result by trust dimension and its own observation IDs:

```
(method, url, role, owner, accessor, trust_dimension) -> hypothesis result
```

A roleless test case does NOT credit a role-specific surface item. A tested case without `dimension_results` leaves all dimensions unknown. `tested`, `confirmed`, and `disproved` dimensional results count as covered only after observation matching; pending, blocked, inconclusive, and unknown do not.
